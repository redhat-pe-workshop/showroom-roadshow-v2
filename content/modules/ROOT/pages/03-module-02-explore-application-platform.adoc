= Module 2: Explore the application platform
:source-highlighter: rouge
:toc: macro
:toclevels: 1

Before you build the developer portal, you need to understand what's already running on the cluster. OpenShift is more than a container runtime -- it's an application platform with integrated CI/CD, GitOps, developer workspaces, and secrets management. These capabilities form the foundation of your IDP.

In this module, you'll log into the OpenShift console and Argo CD to see what's available and understand how the infrastructure is managed.

== Learning objectives

By the end of this module, you'll be able to:

* Identify the pre-installed operators that provide application platform capabilities
* Navigate the OpenShift console to verify operator availability
* Log into Argo CD and understand the app-of-apps deployment pattern
* Distinguish between the infrastructure project (read-only) and your workshop project (read-write)

== Exercise 1: Explore OpenShift

The OpenShift cluster has been pre-configured with operators that provide the building blocks for your IDP. You don't need to install any of these -- they're ready to use. Your job as the platform engineer is to wire them together through Developer Hub.

NOTE: These specific tools are used in this workshop, but the concepts apply regardless of your CI/CD, GitOps, or secrets management provider.

. Open the **OCP Console** tab and log in with your credentials:
+
* Username: `{user}`
* Password: `{password}`

. Navigate to **Operators > Installed Operators** and verify the following are installed:
+
* **Red Hat OpenShift GitOps** -- Argo CD for declarative deployments
* **Red Hat OpenShift Pipelines** -- Tekton for CI/CD pipelines
* **Red Hat OpenShift DevSpaces** -- Cloud development workspaces
* **Red Hat Developer Hub** -- The Backstage-based developer portal you'll configure

. Note the other operators present on the cluster. These provide additional platform capabilities:
+
* **Red Hat Quay** -- Container image registry
* **External Secrets Operator** -- Syncs secrets from Vault to Kubernetes
* **Red Hat Advanced Cluster Security** -- Container image scanning and policy enforcement

=== Verify

You should see all operators listed with a status of **Succeeded** in the Installed Operators view.

== Exercise 2: Log into Argo CD

Argo CD manages the cluster infrastructure using a pattern called **app-of-apps** -- a single parent Application that deploys and manages all the child Applications (GitLab, Keycloak, Vault, Pipelines, and more). You'll use this same pattern to manage your Developer Hub configuration.

. Open the **Argo CD** tab

. Log in using **Log in via OpenShift**, and selecting the **developers** identity provider.
+
* Username: `{user}`
* Password: `{password}`
+
You may need to authorise access when prompted.

. Once logged in, explore the Applications view. You'll see the infrastructure apps that were deployed by the platform team:
+
* `app-of-apps` -- The parent Application
* `gitlab`, `keycloak`, `vault`, `quay` -- Supporting services
* `developer-hub-prereqs` -- The Developer Hub operator subscription
* `pe-workshop-argocd` -- Your workshop project (just created)

. Click on **`app-of-apps`** to see the dependency graph. This shows how all infrastructure components are orchestrated.
+
NOTE: You have **read-only** access to the `default` project. You can view but not modify any infrastructure Applications.

. Click **Settings > Projects** in the left sidebar. You should see the **pe-workshop** project. This is where you'll create your Developer Hub Application in the next module.

=== Verify

* You can see the infrastructure Applications in the `default` project
* The `pe-workshop` project is visible in Settings > Projects
* You cannot sync or delete any Applications in the `default` project (read-only)
