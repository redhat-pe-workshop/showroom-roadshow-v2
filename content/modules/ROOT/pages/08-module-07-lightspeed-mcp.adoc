= Module 7: Add AI assistance with Lightspeed
:source-highlighter: rouge
:toc: macro
:toclevels: 1

Your Internal Developer Platform now has SSO, a populated catalog, and self-service templates. But developers still need to know where to look, what to search for, and how to navigate the platform. What if they could just ask?

Red Hat Developer Hub Lightspeed provides an AI assistant built into the portal. Combined with Model Context Protocol (MCP), Lightspeed can query the software catalog, retrieve documentation, and provide contextual answers -- all from a chat interface.

In this module, you'll enable Lightspeed as the final piece of Parasol's IDP.

== Learning objectives

By the end of this module, you'll be able to:

* Understand how Lightspeed integrates with Developer Hub
* Explain how MCP connects the AI assistant to the software catalog
* Enable Lightspeed by switching to the final configuration overlay
* Use the AI assistant to explore the catalog with natural language

== Exercise 1: Switch to the Lightspeed overlay

The `overlays/05-lightspeed/` overlay adds:

* **Lightspeed sidecar containers** in the Backstage CR (llama-stack for LLM inference, lightspeed-core for the service layer)
* **RAG data** -- pre-built embeddings of Red Hat Developer Hub documentation for context-aware answers
* **MCP server configuration** -- connects Lightspeed to the Backstage catalog API so it can query real catalog data
* **Lightspeed dynamic plugins** -- frontend chat UI and backend API

. In the **Argo CD** tab, click on your **developer-hub** Application

. Click **App Details** and change the **Path** from:
+
----
overlays/04-templates
----
+
to:
+
----
overlays/05-lightspeed
----

. Click **Save** and wait for the sync to complete
+
NOTE: This overlay adds sidecar containers to the Backstage pod. The pod will restart and take 2-3 minutes to become ready as it downloads the RAG data and starts the LLM inference service.

* Sync status: **Synced**
* Health status: **Healthy** (may take 2-3 minutes)

* Lightspeed responds to questions about catalog entities

== How it works

Lightspeed runs as **sidecar containers** alongside the Developer Hub pod:

* **llama-stack** -- Provides LLM inference using a pre-configured model. Includes RAG (Retrieval Augmented Generation) data from Red Hat Developer Hub product documentation.
* **lightspeed-core** -- The service layer that coordinates between the chat UI, the LLM, and MCP tools.
* **MCP (Model Context Protocol)** -- A standard protocol that gives the AI assistant structured access to the Backstage catalog API. When a user asks about a service, Lightspeed uses MCP to query the catalog and ground its response in real data.

This architecture means Lightspeed answers are contextual -- it knows about your specific catalog entities, not just generic documentation.
